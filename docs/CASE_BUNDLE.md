# 本地病例抽帧与平台交接

本地服务和阶段模型运行在 Mac（当前 Linux 开发环境也可运行）；局域网浏览器上传的视频写入**服务端**的数据目录，而非访问者的浏览器设备。启动时用 `--data-dir` 或 `LOCAL_ANNOTATION_DATA_DIR` 指定 Mac 本地磁盘位置，视频库页面会显示实际保存路径。

## 操作

1. 上传视频并完成阶段、质量、侧别、征象和病例信息标注，保存后完成复核。
2. 回视频库选择抽帧率（默认 4 fps），在病例卡片点击“抽帧”。后台只对**有效观察且可判读**的阶段抽取原尺寸 JPEG，关闭页面后继续。
3. 抽帧完成后勾选一个或多个病例，点击“导出所选病例包”。所选病例须全部完成当前版本的复核和抽帧。修改标注后旧帧标为过期，需要重新复核、抽帧。
4. 在原平台 **debug → 视频帧标注** 点击“导入本地病例包 ZIP”，直接选择下载的 ZIP。无需解压；原平台验证文件、图像和清单后一次性登记病例和帧。
5. 新病例在帧列表和帧工作区带“本地导入”标签，可使用原有图像分割编辑器绘制、保存和确认。通过病例信息链接或视频标注列表进入的页面只读，只展示病例、阶段、征象和结构化报告，**不包含播放器与时间轴**。

导入保留原始来源病例编号，同时在平台使用独立的病例编号，避免与已有病例合并。管理员能查看全部；新导入病例默认只授权上传医生，后续可在现有病例权限页面分配。

## 包内内容

```text
manifest.json
cases/<portable_id>/
  annotations.json     病例、阶段、征象标注及人口学字段
  report.json          已保存标注的结构化整理
  frames/*.jpg         可判读有效阶段的原尺寸帧
```

不包含原视频、账号或凭据。结构化报告整理医生已保存的诊断、备注、阶段、征象和时长，不自动生成新的诊断，不把未标注内容解释为阴性。

协议为 `sam-annotation.case-bundle.v1`。`portable_id` 来自本地实例与病例标识；复制整个数据目录后保持身份。清单保存来源视频 SHA256、尺寸与时长、复核版本、抽帧率、每帧时间、所属阶段、MD5、SHA256 和大小；清单自身也有内容摘要。

抽样时间是每个合格区间 `[start,end)` 中的 `start + k/fps`，每段一次顺序解码，选择目标时间或之后的首个源帧，不使用会选择更早图像的最近帧重采样。时间戳表示计划采样点，源视频帧率较低时多次采样可能落在同一个实际帧；当前解码实现会拒绝帧数不足的输出，不发布不完整结果。

## 导入规则

- 同一来源、同一病例快照重复上传不会重复建档，也不会覆盖已绘制的帧标注。
- 同一来源病例已经导入后，修改版本的重新导入返回冲突，保留原病例与帧标注；暂未提供合并／覆盖导入功能。
- 导入病例的临床信息在服务端也禁止修改，不只是隐藏编辑按钮；图像帧标注继续可编辑。
- ZIP 有路径穿越、重复文件、符号链接、缺失文件、摘要不符、非法区间或超限压缩等情况会拒绝。导入还核验 JPEG 尺寸并实际解码。
- 单个 ZIP 最大 2 GiB，最多 100 个病例，每例最多 20000 帧；超出时降低抽帧率或分批导出。

当前原平台接收端仅在 debug 启用，帧保存在该平台本地数据目录的 `frames/local-imports/`，原视频仍仅存在本地端。当前任务完成图像帧标注交接；未将这些新帧发布至 wg-data 的远程训练产物存储。两站共用元数据，所以 debug 导入属于真实业务写入，测试必须使用独立临时数据库；仅部署代码不写入演示病例。

## 验证

`tests/test_extraction.py` 验证真实 FFmpeg 抽帧、计划时间、准确定位、复核失效和 ZIP 合约。`tests/browser_smoke.py` 验证本地页面操作及实际 ZIP 下载；`tests/browser_transfer.py` 将这个浏览器导出的 ZIP 上传至隔离的原平台，验证标签、只读病例页、帧区域保存和现有图像编辑器。

wg-data 的一段 9911196 字节小视频已通过鉴权 HTTP 复制到本地并校验原 SHA256，登记在本地视频库。真实视频抽帧测试只在临时库中使用明确的软件测试区间，不作为医生判断，也未写入线上病例或 Git。
